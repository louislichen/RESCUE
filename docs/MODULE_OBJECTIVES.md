# 从目标评价与优化模块

用户于2026-10-18要求将调度效率与模块是否实现目的分开评价。本轮执行针对性
研究，原长文本独立测试仍暂停；不接着跑SOTA排名，也不使用那71条测试结果调参。

最终SD输出仍须与相同精度Target匹配。这里的“质量”首先指草稿分布和贪心预测
与Target的一致性，不把接受率写成最终任务正确率提高。

| 对象 | 要实现的目的 | 主要指标 | 必须控制的代价/条件 |
|---|---|---|---|
| 调度 | 缩短关键路径、减少截止时等待 | 轨迹不变时整请求/解码TPS、长度就绪率与等待、各阶段host/stream区间 | 相同模型、精度、动作与模块参数；profile与正式计时分开 |
| M1选择 | 少读上下文，同时保留或提高草稿质量 | 同预算贪心一致率/每轮接受量；相同质量下参考位置数；预算—质量曲线 | 相同前缀、实际token预算、刷新频率、sink/recent；选择/gather成本 |
| M2注入 | 修正M1之后仍然缺失的信息 | 同前缀的纠错率、伤害率、净纠错；固定长度真实SD接受前缀 | 只切换注入；对照含native、旧mapper、目标驱动mapper；映射/门控成本 |
| M1+M2 | 以较少参考恢复草稿质量 | 小预算组合是否达到大预算/完整读取质量；真实SD每轮提交量 | 相同长度策略，分别保留M1、M2及组合消融 |
| M3长度 | 少做无效草稿且避免过早停止 | 废弃草稿/已提交token、可避免拒绝尾部、Draft forward/提交、验证次数/100提交 | 相同M1/M2和预算；同时看整请求TPS与模型/决策成本 |

分布KL、Target首选token的概率/间隔、分布重叠量是质量诊断。注意力质量覆盖和
归一化A·V读取误差是M1的机制代理，不能替代实际预测质量或独立内容语义证据。
工作KV位置数与读取位置对只是参考/流量指标；完整backing KV及prefill仍保留，
不能写成等量物理缓存压缩。硬件带宽还需实际测量，位置对不是实测HBM字节。

令P/A分别为提出/接受的Draft token总数，R_reject为发生拒绝的轮数：废弃量=P−A，
拒绝点之后可避免的尾部=P−A−R_reject。第一个错误token用于发现分歧，单独列出；
全接受后的必要cache补算计入Draft forward，不伪装成提出的草稿。M3不能仅靠
缩短长度宣称成功：还必须记录增加的Target验证轮数和提交效率。

## 本轮实现与实验

入口：[模块目标工具](../rescue/objectives.py)、[CPU重算与长度标定](../rescue/objective_audit.py)、
[配对诊断/训练/系统运行](../rescue/module_study.py)。结果在
[module_objectives](../exp/module_objectives/README.md)。

1. 用既有开发完整记录，分别重算同预算M2开关、同预算M3开关与参考预算变化。
   比较不同最优配置的总TPS不再被当作单模块归因。
2. 对同一Teacher强制前缀、共同原生Student历史，比较full、Teacher/J联合Top-k、
   分层512/1024与M2新旧权重。每query刷新，以测当前选择质量；这不是原刷新
   策略的吞吐实验，也不是M2历史影响的完整滚动测试。
3. 在旧rollout保存的末层query上，以Teacher top1间隔、输出KL、原生正确预测
   的间隔保持及残差惩罚训练mapper。训练内监测优先按实际贪心命中、再按KL选
   checkpoint，允许保留原权重；仅当前query局部重放，不反传历史cache。
4. 用训练内监测的整组提交数/成本标定长度的accept偏置与条件深度先验混合。
   单起点oracle regret只作诊断，不作为请求吞吐的替代。拟合成本与旧mapper
   状态的局限由后续真实SD验证；纯深度先验是无注意力对照，不能算注意力成功。
5. 提前发布实际首token注入摘要：末层attention内摘要已可得时通知异步规划器，
   与首token剩余attention/O/MLP/词表计算重叠。串行和原发布方式保留，默认关闭
   新选项；不使用未来接受结果。CPU检查要求动作和输出轨迹不变。
6. 三篇先前未使用的开发文档229/231/251、8K/16K、96输出上限、两次计时，
   对匹配的模块开关和串行/异步早晚发布测量。训练文档246/248仅用于质量诊断
   与预热；profile使用训练246，单独记录且不提供正式吞吐数值。

这是一个新开发pilot；三篇文档不足以替代完整论文实验或预先暂停的独立测试。
新参数不能继续使用此前“未看过”的测试身份声称已经通过确认。

Host区间含CPU调度，CUDA event区间含stream排队/空闲；异步区间可重叠，不能
求和称作独立kernel成本或GPU忙碌率。实际净调度收益以未profile的同轨迹请求为准。

## 随后的指标优化

用户继续授权实现优化，已完成[新一轮报告](../exp/module_opt/REPORT.md)：M1锚点
候选没有达到滚动质量目标；M2 query条件方向有小幅净纠错信号，但额外读取
条件没有继续改善；M3 ratio减少废弃和Draft forward，却增加Target验证、没有
净加速。所有结论依各自同配置对照，失败候选未变成默认。新确认是303/306/327、
128输出协议，不能与本页前述229/231/251、96输出直接混算。

这进一步要求优化目标同时约束：M2纠错与伤害、M3废弃与验证成本、M1参考预算
与真实滚动质量。只优化KL、注意力质量、少参考或少废弃，都不能代替模块目的。
