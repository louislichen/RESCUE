# 长文本系统优化与SpecExtend比较

用户当前授权：按高效后端、低成本选择、按需刷新、联合rollout注入训练、注入条件
长度控制的顺序优化；先比较SpecExtend。暂不运行其它SOTA基线。
2026-10-18最新指令为先暂停查看进展；GPU与后处理队列已停止，不自动恢复。
独立测试71/320，详见`out_comparison_v4_20261017/PAUSED.json`及[REPORT.md](REPORT.md)。

工程目标：8K/16K完整请求TPS相对匹配SpecExtend提高至少10%，文档配对95%区间
下界大于0；该门槛是本轮工作定义，不是已达到的结果或普遍SOTA结论。

- 新GovReport原始语料按原train/validation/test构造12/6/12篇自然长报告，文档
  SHA256互斥，均从索引200之后选择；不依赖生成结果，不重复文本拉长上下文。
- 每篇嵌套2K/4K/8K/16K输入，生成上限256，后续512作为独立扩展；真实EOS照常停止。
- 训练用于拟合，development用于预算/刷新/路由/长度选择，test在配置冻结后打开。
- 先固定长度，分离后端、选择、注入；再评估新长度控制。零注入必须保留作诊断，
  不能作为完整三模块成功的替代。共同后端改进同样给予SpecExtend。
- Qwen2的chunk检索控制与原版Vicuna树/Flash/Hybrid引擎分别标注，不能把前者
  自动称为完整SpecExtend。跨模型、精度、硬件的速度不直接相除。
- 首轮BF16冒烟在4K发现与AR参考不一致，保留`out_probe_v1_20261017`为失败诊断，
  不用于正结果；FP32高效注意力独立复测，不能静默跳过失败请求。
- 每次正式测量保存执行源码、数据/权重哈希、配置、原始轮次、参考与完整矩阵；
  独立统计单位是文档，计时重复不是独立样本。

当前实现还包含首token注入摘要驱动的36维长度模型：在第二个token前，汇合原31维
注意力/读取特征与实际门控、归一化残差、被注入位置的当前工作注意力质量、层比例、
token比例。串行和异步路径都有CPU快照/轨迹一致性检查；旧31维checkpoint保留。

首轮训练使用6篇训练报告的4K/16K、64输出上限，24/24输出一致。末层mapper
240条拟合query、48条内部监测query；六个epoch均未优于初始监测损失，因此保存
原权重。387个真实轮次用于长度拟合。第二轮已匹配混合prefill和256输出完成
24次采集，288条重放query、1811个轮次；末层mapper内部监测代理损失约下降1.02%，
风险模型内部监测NLL为0.603762。它们不是独立测试吞吐改善，不隐藏第一轮负结果。

完整树引擎的Qwen2适配已通过2K/8K、8/32节点四次输出检查，保留归档树、跨模型
检索和Hybrid Tree路径；修改QKV bias、RoPE基数、GQA缓存头数/精度及可用词表。
FP32 Target使用efficient-SDPA前缀输出/LSE替代不支持FP32的Flash前缀核。它是
完整算法流的Qwen适配，不是原版Vicuna/FP16复现。检索控制另外计时，择优而非
只选慢树对照；未运行EAGLE-3、DFlash等其它性能基线。

后端还提供可选QKV与MLP投影打包；正式启用时同样给予两种SpecExtend对照，并
记录一次准备时间与额外显存。低精度prefill是显式配置，不冒充原FP32全程数值等价。

初轮矩阵入口为`rescue.long_benchmark`，其独立test已延后。完整原始请求和源码
保留，不改写已经执行的协议。最终速度与是否达到门槛仍以完成后的记录为准。

初轮开发114请求完成后，为补齐50/64树节点、固定2及优胜1024预算的无注入
对照，测试计时被延后且保存零测试计时记录。补充入口为`rescue.long_refine`，
独立test仍只在选择冻结后执行，核验用`rescue.long_refine_audit`。跨开发批次以
各自同时测量的检索锚点归一化，复测配置替换其旧分数，不混算原始绝对TPS。
